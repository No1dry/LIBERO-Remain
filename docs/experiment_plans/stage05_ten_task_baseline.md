## 4. 新评测端点：完成即结束，不要求模型会FINISH

统一H=520个策略控制步，20Hz；状态构建/settle不计入策略步或路径长度。

每个真实控制步读取官方目标谓词和评价证据，不额外调用模型、render、step或改变RNG。全部目标为真且相关可移动目标已释放，连续K=4个控制间隔（5个相邻观测）确认后结束；步数和距离计到确认步，不回溯裁剪成更短路径。关节目标不套用“物体释放”要求。

H前有上述确认，记exit_reason=goal_confirmed；否则到H记horizon。确认可以发生在chunk内部，剩余候选动作丢弃、不执行；不补一次模型查询。没有W150保持、脚本归位或自动开爪，不把评价端结束记作模型FINISH。只允许评价端读取GT判断何时结束，不把GT作为策略输入或中途改写动作。

明确违规事件已发生时可继续记录到相同目标端点或H，但成功标签为sticky false；不因发生违规就提前截短路径。NaN/进程错误/证据缺失属于技术故障，不伪装成模型任务失败或目标完成。原模型意外返回STOP不能冒充goal_confirmed。

## 5. 两个主报告项及自动事件

### 5.1 合规任务成功率（百分比及n/N）

成功必须：H内确认目标完成；初始A全程保持；无下面明确禁止事件。漏完成B、破坏A、确认错抓/错放或确认严重场景破坏均失败。轻微触碰、观察、靠近空位、未抓住物体的简单尝试不直接失败。

为避免本轮变成通用行为裁判工程，第一版只采用下列可自动复算的物理事件；不得宣称它识别了所有语义冗余或所有场景损害：

- 确认错抓：对任务无关的可移动物体，真实双指pad接触夹持与相对初态至少2cm的上抬同时持续K=4个间隔。仅闭爪、单侧接触、碰撞推出不算此事件。任务目标、任务容器/支撑及确有任务作用的部件按任务角色表处理，不把篮子、盘子、抽屉误列为普通干扰物。
- 确认错放：初始不在任务目标容器/承载面上的无关物体，新增满足相应In/On目标关系且已释放，持续K=4个间隔。移出后不擦除事件；初始已有无关物体不要求清理。不把篮子专用谓词硬套到炉子/抽屉任务。
- 严重破坏第一版自动判据：初始由工作台支撑的非目标可移动物体，整个碰撞几何世界z上界连续K=4个间隔低于该工作台支撑面2cm，确认掉出工作台。其他位移/倾角保留原始记录作诊断，不在看到模型表现后临时加罚。
- 已完成目标A在任一记录步不再满足官方谓词，记goal_regression并保持失败；这与“轻微移位但成果关系仍成立”区分。

这些物理默认参数是本轮操作定义，不是学到的判据。X若发现明确不可实施或可靠性问题，首轮交付中一次提出有依据的替代；在真实基线启动前冻结，不根据100条结果调阈值。证据不支持的事件用unknown，不能默认“没有违规”。复用已经验收的测量组件；不为本轮新增头训练或几何校准实验。

自动失败原因可多标签，保留到每episode日志，不再增加一排主metric。仍同时保存未经合规过滤的官方目标达成事实，便于分析“做完但做错过”的差别。

### 5.2 实际末端路径长度L，单位米

保存每一个控制步（含step0）相同TCP/eef site的世界坐标p，L=sum(norm(p[t]-p[t-1]))。不是action向量范数、不是手掌代理点、不是每8步采样一次。保存site身份、坐标系、每步增量和累计值，且离线可复算。

全部episode原始L和步数均保留；主效率比较为成功episode平均L，同时报告适用n/N。某任务无成功时成功条件L为N/A，而不是0。失败episode的长度只作带失败状态的诊断，不把“短但失败”当好结果，不把L直接命名为冗余率。
