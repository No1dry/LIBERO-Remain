## 2. 总体判断

**我赞同 Codex 对四条路线的功能拆分，以及冻结底座、独立选择器和内置选择头必须分别描述的要求。**它纠正了一个容易出现的混淆：学习“现在该做什么”的模块可跨模型复用，不等于每个底座都能执行它给出的子目标，更不等于底座权重学会了新能力。

两稿对问题本身并无根本冲突。独立稿更广，涵盖感知绑定、数据、训练、控制与高成本候选；Codex 更聚焦于两种高层决策器及其数据和历史接口。35 个候选不应对等比较为 35 条完整体系；四路线也不应变成四个必须堆叠的模块。

**我在第二轮调整优先组合：**如果要充分利用已复现的多种 VLA，并优先研究可迁移的决策模块，首选“任务角色与目标状态条件化的独立选择器 + 真正被读取的有限证据历史 + 冻结 VLA 执行接口”。现成 VLM 作为替代决策器和强系统对照。独立稿首选的“部分完成微调 + 内置剩余目标条件化”保留为另一条完整学习路线，不再作为通用选择器的必需前置项。

这是明确的排序更新，不是认为原独立稿错误，也不是因为 Codex 已经证明哪条路线更好。调整理由是：独立选择器可以使用状态/角色标签，而不必先获得完整正确动作；冻结底座便于检查同一决策模块换 VLA 后的边界；当前错抓与目标选择证据给了这条路线合理切入点。以上只说明值得选择，尚未证明它足以解决低分任务，也未证明成本必然更低。

如果最终论文要声称“VLA 本体学会了剩余任务执行”，则应选择内置学习路线并承担训练成本。只训练外部选择器时，应写成“学习一个支持 VLA 剩余任务执行的决策模块/系统”，不能混用两个主张。

## 4. 真正的差异，以及我接受或保留什么

### 4.1 冻结底座路线与内置学习路线：目标不同，不强行合并

独立稿组合 B 优先 M02 + M11 + M19，即角色绑定、子集微调和内置目标条件化；Codex 更偏向 ①+④ 或 ③+④，即不更新 VLA。

我接受把这两类完整体系并列，而不是规定“先把 VLA 微调好才能研究选择器”。动作微调解决状态—动作覆盖，选择器解决状态—决策映射，二者都可能有价值，但成本、能力归属与失败解释不同。

同样不应把“冻结”当作无需学习的证明。③的选择器通常仍需训练，观测模块、标签质量、历史利用和校准也可能需要数据。选择器若只在一个任务集合上学会任务编号到 B 的映射，不比任务内微调更能证明通用性。

### 4.2 我会进一步强调任务角色绑定

Codex ③偏重“目标是否满足、当前选哪个子目标”；独立稿 M02/M07/M15 更强调“当前图像中哪个实体对应这个目标，哪些是必要部件，哪些是普通干扰物”。

这一差别值得保留。基线中两个低分入篮任务出现了先抓奶酪或牛奶，单纯输出语义上正确的“抓番茄酱/黄油”可能仍然不能改变底座实际抓错对象的行为。因此选择器至少需要可核验的实体/区域证据；是否需要把该证据进一步传给动作控制器，要取决于实际接口与诊断结果。

这里不能偷换接口：**如果对 VLA 只发送文本，选择器的实体定位并没有直接约束 VLA 的手。**文本接口无效时，可以选择训练对象条件控制器、引入经适配的区域输入或纠正动作学习；这些都属于增加系统范围，不能继续称作原样冻结、无需适配的语言模块。

### 4.3 现成 VLM 可免新增任务训练：接受，但单列这条具体实现

独立稿 M05 主要按需要状态判断/重写数据的模块描述；Codex ①指出可直接用现成 VLM 的能力，在本任务上不新增训练。

这是值得补充的实用方案，应与“训练专用选择器”分列。无新增任务训练不等于无预训练数据、不用开发集选择提示、不增加计算，也不代表当前图像中的接触和释放一定可辨。

①可成为完整系统方法，不必只作为给③造数据的工具；它也不必成为③开工前的强制试跑阶段。两者优劣应由目标、成本和可验证收益决定。

### 4.4 规则历史是可行起点，但必须有信息增量

独立稿同时提供了学习式时序记忆 M09、轻量证据记录 M27 和恢复触发 M28；Codex ④更明确允许用规则维护历史，由①或③读取。

我接受这一简化，不要求为了“有记忆”先训练循环网络。更重要的问题是，历史里是否增加了决策需要的信息，例如“上一段接近的对象”“观察到的夹持变化”“哪一项完成证据曾可见”“现在遮挡且尚未复核”。

如果历史只记录“失败了三次”，却无法区分目标身份错、抓取失败和遮挡，那么它可能只会触发重复重试。规则记录的事件若来自学习式视觉检测，其检测训练与误差仍需披露；不能把整个链条说成无需训练。

### 4.5 完整方法开发不应被前置 MVP 锁住

独立稿第6节与“先建立简单基线”“先证明”等表述容易被理解为：未先跑完所有诊断，就不能实现完整方法。Codex 明确不同意把 MVP 设为前置门槛。

**我接受这一修正。**未来若用户选定完整方法，可以直接设计与实现，并预留组件开关；必要对照和消融用于评估结论，不必全部先于工程开发完成。基线、模块诊断、泛化检验仍是论文证据要求，但不是未经用户选择就设置的串行审批关卡。

本轮仍只有讨论，没有因此获得实现或实验授权。

### 4.6 不自动扩展顺序议题与 benchmark

独立稿 M14、多目标 M06/M34 及新增 01/11 等提议包含更宽研究空间。Codex 文档记录：示范顺序与物理依赖另作议题，不并入此次方法组成或新增评测要求。

我据此将 **M14 从当前推荐方法中移出**，只保留独立稿里的研究候选记录。多目标依赖图、全部完成后的保持窗口和扩 suite 也不是当前四路线的默认交付项。

原有 mask10 可以支持当前条件下的系统比较；若将来主张“任意完成子集、任意目标组合”，就需要相匹配的证据或降低主张。提出这个证据边界，不等于现在自动要求扩 benchmark。

## 6. 应明确否定的版本与需要重组的组合

### 6.1 应否定的主张或实现

这些主要是否定候选的错误版本，不是说 Codex 已经犯了这些错误。

1. **“主要失败是重复操作 A，强保护 A 就够了。”**基线 A 回退仅 1/80，不能解释大量错抓和未完成。保留是约束，不是已证主要瓶颈。
2. **“已完成识别正确，就一定选对并抓对 B。”**从状态识别到语义选择，再到实例绑定与动作执行，中间至少有三处可失败。
3. **“只需把正确短指令交给任意 VLA。”**短指令可能分布外，底座也可能忽略、误绑定或无法从当前姿态执行。
4. **“独立选择器和 VLA 内部头可以共用通用性宣称。”**二者输入、特征与训练接口不同；改内部动作头已不是原样冻结的插件。
5. **“连续尝试失败，所以该目标已经完成/应永久跳过。”**失败、没证据和完成是不同状态；重复尝试只能触发新判断。
6. **“冻结 VLA，所以整个系统没有训练成本。”**③、视觉检测和校准可能需要训练；①也有预训练与推理成本。
7. **“普通示范切后半段即可覆盖所有外部完成状态。”**机器人状态、接触与遮挡可能不同，必须检查可接续性并承认原 checkpoint 的潜在见过情况。
8. **“先把所有 MVP 和对照跑完，才允许完整方法开发。”**不设此门槛；保留完整方法的开关与之后的证据要求。
9. **“改写指令后只按改写目标评分。”**原完整任务、历史违规和已有成果保持要求不变。
10. **“STOP、零动作、无错抓就是改进。”**当前评价端已终止；必须同时完成剩余目标，不能以停滞取代执行。
11. **“VLM 生成的证据文本就是可信物理证据。”**它只是预测依据/输出，需用独立标签和物理评价核验，不能自评自证。
12. **“两稿一致，所以这些机制已成立或具有新颖性。”**一致只降低了理解分歧，不能替代实验或相关工作检查。

### 6.2 组合的重组

**①与③：主决策器通常二选一。**它们承担相同层级的“看当前状态、选当前目标”工作。两个都在线时，应明确哪一个有最终选择权、何时回退、输出冲突如何处理；否则可能只是多一次推理和两种错误叠加。

若保留双决策版本，推荐“专用③常规决策，低置信时请求①补充判断，③按预定规则接受/拒绝该建议”的明确结构，或直接选择①为最终裁决者；两者不可在实验后按结果临时切换。增加调用和延迟全部报告。这是可选扩展，不是首选默认。

**④不再包装成另一套规划器。**它负责保留证据与尝试结果，①或③负责解释和选择。若④自己包含完整目标决策网络，则需重新命名职责并消融，避免将相同计算重复算成两个贡献。

**②+③+④拆成两个明确版本：**

- **微调执行器 + 外部③ + 历史④：**可以成立，但外部③是否仍有增益需与单独②比较；若只②提升，则不保留冗余决策层。
- **微调 VLA + 内置剩余表征 + 时序条件：**属于整体模型方法，用 M11/M19 等描述；不能借用外部③的接口通用性。

模块化组合还有一个具体分布问题：如果②训练只使用原完整指令，③部署却持续给短子目标，二者并不自然兼容。应明确执行器最终接收的文本形式，让动作训练覆盖相应输入，或独立说明冻结执行器已有的兼容性证据。这个接口设计属于完整方法自身，不是要求预先运行 MVP 的理由。

**①辅助训练③：明确伪标注与教师边界。**VLM 可提供目标文本解析、候选状态说明或偏好建议，但应抽样核验、保留未知与冲突。用于训练的提示和评测来源也需隔离。它不是 M21 特权状态教师的等价替代，不能自动获得正确标签；后者也不能保证其动作选择无误。

**自适应 chunk、保护层、STOP：分别处理。**子目标改变后使旧 chunk 失效，是确保决策生效的基本接口要求；学习何时缩短 chunk 是独立改进。保护层可选且必须保留可行动作；STOP 当前不加入。不能把这三者打包成必需执行模块。

## 7. 第二轮推荐的完整方法

### 7.1 首选：学习任务角色与剩余目标选择，冻结执行器

完整结构为：

> 原完整任务与 RGB/本体状态 → 目标关系与实体角色判断 → 结合有限证据历史选择当前操作目的 → 通过受约束的子目标接口驱动冻结 VLA → 记录真实可观测的尝试结果，再更新判断。

这里“受约束”指目标必须来自原始任务或服务于原任务的必要观察/操作，不是增加真实状态权限。评价端始终按原任务的全部关系和过程要求评分。

建议将完整系统定义成四个职责明确的部分：

1. **任务条件化表示。**以目标描述、实体角色和关系为条件，而非任务编号→A/B分类。支持已满足、未满足和观测不足；必要部件与普通干扰物分开。
2. **独立决策器。**结合当前观测与历史，选择继续当前操作、换到另一未完成目标或重新获取证据。多个当前目标都合法时，使用集合标签，避免强制唯一答案。
3. **可核验的证据历史。**保存尝试对象/区域、观察到的状态变化与时间、完成证据及未知项。保留的是观测证据及其置信度，不是不可撤销的“成功宣布”。
4. **冻结执行器接口。**子目标改变时丢弃旧目标未执行动作，按各底座的输入预处理和状态重置约定传递新目标。记录送入的文本、执行对象和调用成本，能区分选择错与执行错。

历史中的夹爪状态必须来自允许的本体观测，物体身份和交互结果必须来自传感估计；不能把评价端双指接触真值、谓词或世界坐标偷偷写进在线记忆。观察与恢复也只能使用实际支持的执行接口，不能把一个自然语言“观察”指令默认当成已经存在的可靠技能。

不必为上述结构引入世界模型、完整场景图或大时序网络。可先采用规则记录历史与专用选择器；是否对历史做学习式融合由模型设计决定。独立选择器必须真实读取历史，若不读取则只能称为单帧选择器。

### 7.2 学什么、需要什么数据

主监督可包括目标关系状态、任务角色/实体绑定、可见证据充分性和允许的当前目标集合。训练仿真真值可生成部分标签，但：

- 满足关系真值不能自动生成“图像可辨”标签；遮挡和歧义需另外标注/验证。
- 状态标签不能自动成为正确动作标签；首选选择器路线正是避免预先要求完整恢复动作，不是声称动作采集问题消失。
- 当前子目标可能有多个合法答案；选择监督应容许集合标签。不由此引入顺序监督、依赖关系学习或新增顺序评测。
- 角色互换与完成状态配对是优先候选数据设计，对应 M12/M15。无关因素变化时可要求高层意图稳定，但不能要求避障动作不变。
- 混入普通 00 和成功/失败尝试证据，避免总是跳过 A 或只学“看到这个任务就选 B”。具体新增条件与数量由未来选定范围决定，不在本轮自动立项。
- 从基线失败中生成训练/开发标签时继续披露已暴露来源；不将同一轨迹帧随机切分后宣称未见泛化。

### 7.3 需要的对照，以及它们回答什么

这些是完整方法的评估结构，不是必须先完成的 MVP 阶梯：

| 对照/消融 | 回答的问题 |
|---|---|
| 冻结原 VLA + 原完整指令 | 整个系统相对原策略改善多少 |
| 现成 VLM + 同等历史/接口 | 专用学习选择器是否比通用 VLM 更准确或更经济 |
| 专用选择器，无历史 | 历史是否提供额外行为收益 |
| 专用选择器，无角色绑定监督 | 角色/实例绑定是否改善实际物体选择 |
| 匹配来源与采集/标注预算的普通子集微调② | 行为收益、动作标注成本与任务适配之间的取舍 |
| 选择器 + 微调执行器（可选） | 选择与动作学习是互补还是冗余 |
| 单独报告的 oracle 状态/剩余指令 | 感知与条件化潜在空间；不能混入主成绩 |

oracle 不提升不能单独证明状态判断无关，因为文本分布和接口可能失效；oracle 提升也不证明部署预测器能达到该收益。当前 00 对照缺口影响因果解释，应在未来评估设计中处理，但不作为此刻自动启动实验的理由。

选择器可使用纯状态标签，②却需要正确动作，不能拿同一份只有状态标签的数据宣称做了公平动作微调对照。应明确匹配训练来源、采集与标注预算，分别记录状态标签和动作标签成本；需要严格同数据比较时，使用共同具备两类标签的数据。行为分数相同但动作标注更少或模块复用更好，也可能有研究价值，须单独证明。

六模型比较优先共享选择器、标签语义、任务目标和评价规则；底座专属输入适配和重规划周期可以有差异，但必须记录。通用性分三层：**接口可移植**、**同一模块无需重训可复用**、**复用后行为收益可迁移**；第一层结构便利不能替代后两层证据。若每换一个底座都重训选择器，结果是“可适配”，不是“同一个模块直接迁移”。不同模型训练覆盖不同则分层讨论，不将 suite 差异解释成单一能力排名。

### 7.4 保留的另一条完整路线

若决定主要贡献应在 VLA 本体，则使用独立稿组合 B：

> M11 部分完成动作训练 + M02/M15 任务角色绑定监督 + M19 预测剩余目标条件化，必要时加入 M12 配对训练。

它需要正确继续动作、模型内部适配与普通能力保留；收益应相对同数据普通 SFT 判断。外部③不是必需，规则历史也不是自动有效。该路线可能更直接改变行为，但不能同时宣称“冻结底座、统一模块、无需动作数据”。

不建议两条完整路线在首篇工作中无差别同时铺开。应先确定主张是跨底座决策模块，还是 VLA 本体学习，再使方法、数据和报告围绕同一个主张组织；这项选择属于研究范围决定，不是已有结果能替用户自动定下的事实。

## 8. 什么结果会使我否定当前推荐

- **子目标与实体判断正确，但冻结底座仍反复抓错：**否定“只改高层文本足够”，转向更强对象接口或动作学习；不能继续只优化分类指标。
- **规则历史没有净收益，或频繁触发错误恢复：**简化/移除④；不能因“闭环”叙事需要而强留。
- **通用 VLM 在相同成本下全面优于专用选择器：**重新评估训练③的价值；可以改选①作为主系统，或缩小③的轻量化主张。
- **普通子集微调在明确匹配来源与标注预算后获得相同泛化：**复杂结构在该设置下未显示额外行为收益；若主张动作标注更少或模块复用更好，须另给证据，否则应报告数据方案或调整研究重点。
- **收益只出现在已见任务和固定 mask10：**限制为任务适配；不能写任意剩余目标重建。
- **违规下降但超时增多、合规成功不升：**否定“安全提升就足够”的结论；检查拒绝/不动策略。
- **00 与部分完成条件同幅提升：**说明可能是通用执行改善；不能仅以总分提高宣称修复了部分完成特有问题。
- **收益来自更多计算或更强预训练教师：**如实报告整个系统成本与来源，用等预算对照分离所提机制，不将全部收益归给一个选择头。

当前结论不是“Codex 的四条路线全对，35 项都要做”。我的取舍是：采纳独立选择器与内置头的清晰区分，保留任务角色绑定作为需要加强的核心，把历史做成真正参与决策的证据输入，以 VLM 和普通部分完成微调作为强对照；移出顺序议题、STOP 和不必要的复杂控制体系。独立稿中更广的候选继续作为冻结记录与后续备选。
